# iFlyProof 开发文档

本文说明项目的架构、接口、数据模型和扩展方式。面向想二次开发或部署的人。

---

## 一、设计目标

- **零外部 Web 依赖**：后端只用 Python 标准库，前端是单个 `index.html`，`git clone` 后 `python3 server.py` 即可跑；
- **本地优先**：转写稿、音频、说话人模型都在本机，不依赖数据库和云端；
- **只做“校对”**：不重新转写、不做 ASR，只消费讯飞听见的分享数据；
- **可替换**：解析、音频、分离三层解耦，方便以后接入其他转写源。

## 四、数据模型

### 1. 前端状态 `S`

`index.html` 里的核心状态是一个对象，存在 `localStorage` 的 `dsh_workbench_v1`：

```ts
interface State {
  title: string;          // 稿子标题
  url: string;            // 第一个分享链接
  urls?: string[];        // 多链接时的全部链接
  audioUrl: string;       // 第一段音频地址（讯飞直链）
  audioId: string;        // 讯飞 audioId
  duration: number;       // 总时长（秒，多段为各段之和）
  items: Item[];          // 转写条目
  names: Record<string, string>; // 说话人标识 → 显示名
  parts?: Part[];         // 多段音频信息
}

interface Item {
  t: number;              // 起始秒（已含多段偏移）
  time: string;           // HH:MM:SS
  spk: string;            // 说话人标识（如 "1"、"胡海良"、"D2"）
  text: string;
  name?: string;          // 兼容旧数据的行内覆盖名
}

interface Part {
  url: string;            // 该段分享链接
  audioUrl: string;
  audioId: string;
  duration: number;
  offset: number;         // 该段在总时间轴上的起点
}
```

### 2. 本地存储键

| 键 | 位置 | 用途 |
| --- | --- | --- |
| `dsh_workbench_v1` | localStorage | 当前编辑状态（自动保存） |
| `dsh_workbench_history_v1` | localStorage | 最近 10 个链接 `{url,title,audioId,t}` |
| `dsh_workbench_docs_v1` | localStorage | 按链接保存的完整状态（最近 5 份），用于命中历史直接加载 |
| `dsh_workbench_db` | IndexedDB | `audio` 存音频 Blob，`model` 存说话人模型缓存 |

### 3. 项目文件 `.trp`

`.trp` 本质是 **zip**（store 模式，不压缩），包含：

```
state.json    # State 的 JSON
audio.mp3     # 合并后的音频（可选）
```

前端用自实现的 `zipCreate / zipRead` 读写，不依赖第三方库。

## 五、后端接口

`server.py` 的 `Handler` 继承 `SimpleHTTPRequestHandler`。

### `POST /api/parse`

请求：

```json
{ "url": "https://shareaudio.iflyrec.com/appShare/share.html?audioId=..." }
```

响应：

```json
{
  "ok": true,
  "title": "2026_11_16_14_19_06",
  "audioUrl": "https://www.iflyrec.com/AudioStreamService/v1/outLinks/...",
  "duration": 13125,
  "items": [
    { "t": 518, "time": "00:08:38", "spk": "1", "text": "……" }
  ]
}
```

实现：

1. 从 URL 提取 `audioId`；
2. 请求 `https://shareaudio.iflyrec.com/ShareAudioService/v1/audioShares/{audioId}`；
3. 解析 `biz.transcriptResult.content`（JSON 字符串），取 `ps[]`；
4. 每个段落用 `ps[i].pTime[0]`（毫秒）作为时间，`words[].text` 拼接文字，`ps[i].role` 作为说话人标识。

### `GET /api/audio?url=...`

- 代理讯飞音频直链，透传 `Range`；
- 只允许 `iflyrec.com` 及其子域名（SSRF 白名单）；
- 支持 `206 Partial Content`，用于拖动定位。

### `POST /api/diarize`

请求：

```json
{
  "url": "https://www.iflyrec.com/...",
  "duration": 13125,
  "numSpeakers": 6,
  "maxSeconds": 600
}
```

- 未鉴权（按使用者要求已移除密码）；
- 有**并发锁**：同时只跑一个，重复请求返回 429；
- 若 `duration` 与本机 `recording_16k.wav` 长度匹配（±10 秒），直接用它，避免重新下载；
- 否则按需用 `Range` 只下载前 `maxSeconds` 对应的字节，再用 `afconvert`（macOS）或 `ffmpeg`（Linux）转 16k 单声道 WAV；
- 调用 `_diarvenv/bin/python3 diarize_sherpa.py <wav> <numSpeakers> [maxSeconds]`。

响应：

```json
{
  "ok": true,
  "duration": 600.0,
  "segments": [
    { "start": 31.59, "end": 34.34, "spk": 1 }
  ]
}
```

### 静态文件

- `index.html` 等由 `SimpleHTTPRequestHandler` 托管；
- 支持 `Range`；
- 屏蔽路径：`/_*`、`/server.py`、`/diarize_sherpa.py`、`/run.sh`、`/recording_16k.wav`、`/server.log`、`/.git`（先 `unquote` + `normpath` 再判断，防编码/相对路径绕过）。

## 六、说话人分离管线

`diarize_sherpa.py`：

1. 用 `wave` + `numpy` 读取 16-bit、16kHz 单声道 WAV；
2. 构造 `OfflineSpeakerDiarizationConfig`：
   - 分割：`sherpa-onnx-pyannote-segmentation-3-0/model.onnx`
   - 向量：`campplus.onnx`
   - 聚类：`FastClusteringConfig(num_clusters=k, threshold=0.5)`
3. 运行 `OfflineSpeakerDiarization.process(samples)`；
4. 按开始时间排序，输出 `{start, end, spk}` 列表。

模型目录结构：

```
_diarmodels/
├── campplus.onnx
└── sherpa-onnx-pyannote-segmentation-3-0/
    └── model.onnx
```

安装：

```bash
python3 -m venv _diarvenv
_diarvenv/bin/pip install -r requirements-diarization.txt
```

## 七、前端关键实现

`index.html` 是一个立即执行函数（IIFE），主要模块：

| 区域 | 说明 |
| --- | --- |
| 状态与工具 | `S`、`utts`、`fmt`、`nameOf`、`displayName`、`save` |
| 渲染 | `makeRow`、`renderAll`、`updateNow`、`setActive` |
| 播放 | `jumpTo`、`safeSeek`、`updateBar`、进度条拖拽 |
| 编辑 | `startEdit`、`startSpkEdit`、`placeCaretAtPoint`、`setCaretAtOffset` |
| 分段 | `doSplit`、`selectionInfo` |
| 删除/撤销 | `doDelete`、`pushUndo`、`undo` |
| 多选 | `pendingDrag`、`beginDrag`、`updateBatchAt`、`copyRows` |
| 说话人 | `buildSpkPanel`、`applyAlias`、`setBrush`、`refreshSpeakers` |
| 导入 | `doImportMany`、`collectUrls`、`addExtraLink` |
| 历史/文档 | `addHistory`、`renderHistory`、`saveDoc`、`loadDocByUrl` |
| 音频缓存 | `loadAudio`、`fetchBlob`、`fetchDiarAudio`、IndexedDB 封装 |
| 项目文件 | `zipCreate`、`zipRead`、保存/打开 |
| 自动分离 | `autoDiarize`、`fetchDiarAudio` |

### 时间定位

- 讯飞只提供**每段起始时间**；
- 点击字时，按“字符偏移 / 总字数”在 `[t, nextT]` 内线性插值，再减 1 秒；
- 双击时用 `caretRangeFromPoint` 反算字符偏移，把光标放在该字之后。

### 多段拼接

- 解析第 i 段时，所有条目的 `t` 加上前面各段时长之和；
- `S.parts` 记录每段的 `offset` 和 `duration`；
- 音频在 `loadAudio` 中下载各段并 `Blob` 拼接，播放器按总时长工作。

## 八、部署建议

### 方式一：直接运行

```bash
HOST=0.0.0.0 PORT=8765 python3 server.py
```

配合 `nohup` 或 `systemd` 常驻。

### 方式二：cron 保活（示例）

```bash
# /home/you/iflyproof/run.sh
#!/bin/bash
cd /home/you/iflyproof || exit 1
if pgrep -f 'python3 server\.py$' >/dev/null 2>&1; then exit 0; fi
nohup env HOST=0.0.0.0 PORT=8765 python3 server.py >> server.log 2>&1 &
```

```cron
@reboot sleep 20 && /home/you/iflyproof/run.sh
*/5 * * * * /home/you/iflyproof/run.sh
```

### 方式三：反向代理 + HTTPS

不建议把服务直接暴露公网。推荐：

- 用 Caddy / Nginx / 1Panel 做反向代理，加 HTTPS 与 Basic Auth；
- 或使用 Tailscale / WireGuard 组网，只在虚拟内网访问。

## 九、扩展点

### 接入其他转写源

在 `server.py` 增加一个 `/api/parse-xxx`，返回与 `/api/parse` 相同的结构：

```json
{ "ok": true, "title": "...", "audioUrl": "...", "duration": 123, "items": [...] }
```

前端 `doImportMany` 里按域名选择接口即可。

### 增加导出格式

在 `exportBtn` 的处理函数里，把 `S.items` 转成 SRT / Markdown / docx 等格式下载。

### 多人协作

当前是“各浏览器各存一份”的设计。若要协作，需要：

- 增加服务端存储（SQLite/文件）与文档 ID；
- 用 WebSocket 或轮询同步；
- 增加账号与权限。

## 十、开发约定

- 前端不引入构建步骤，保持 `index.html` 单文件可直接运行；
- 后端不引入第三方 Web 框架，尽量只用标准库；
- 新增接口遵循 `{ ok: boolean, error?: string, ... }` 的返回约定；
- 任何用户内容都不要写入服务端日志；
- 提交前确认没有把真实音频、会议文字、密钥提交进仓库（见 `.gitignore`）。
